# Thème & Système de Tokens

Ce starter n'utilise **aucune librairie UI propriétaire**. Le thème repose entièrement sur des
**design tokens** générés en variables CSS, consommés par les composants.

## Trois couches, trois mots

Le mot « thème » désigne une seule de ces trois couches. Elles se superposent, de la plus
large à la plus étroite :

Un hook ne remplace pas un token : dans la grande majorité des cas il **pointe** vers un
token. Retoucher un espacement pour tout le kit = viser le token ; retoucher la hauteur du
seul bouton `small` = viser le hook.

La couche « hooks » a elle-même deux étages, que la cascade CSS enchaîne toute seule :

```css
var(--ui-checkbox-box-size, var(--ui-form-control-size, var(--size-components-2xs)))
/*      ↑ le composant          ↑ la catégorie             ↑ le token               */
```

Les hooks de **catégorie** viennent de `_ui-config.scss` et portent son nom
(`$form-control-size` → `--ui-form-control-size`). Ils servent quand une valeur est partagée
par une famille de composants **et** que le token qu'elle vise sert ailleurs : ici
`--size-components-2xs` alimente aussi `ui-tag`, donc retoucher le token dépasserait la cible,
alors que `--ui-form-control-size` ne touche que la case à cocher et le radio.

## Pipeline

```
design-tokens/*.json        (source DTCG, variables Figma)
        │  pnpm tokens:build  (scripts/tokens.build.mjs, réglé par tokens.config.json)
        ▼
packages/ui-kit-react/src/styles/generated/_tokens-*.scss   (variables CSS)
        │  pnpm kit:build
        ▼
@4sh/ui-kit-react/styles.css   (jetons + couche de base + classes utilitaires)
        +  le .scss de chaque composant, compilé dans son propre chunk
```

Les **semantics référencent les primitives** (`var(--primitives-*)`), ce qui permet le switch
de marque/mode sans duplication.

## `UiThemeProvider`

Un fournisseur unique, exporté par `@4sh/ui-kit-react/theming`, pilote ces deux attributs sur
`<html>`. Il est **headless** : il ne fait que poser un attribut, tout le rendu découle des
tokens CSS. On l'enveloppe une fois autour de la racine de l'application :

```tsx
import '@4sh/ui-kit-react/styles.css';
import { UiThemeProvider } from '@4sh/ui-kit-react/theming';

createRoot(container).render(
  <UiThemeProvider>
    <App />
  </UiThemeProvider>,
);
```

- **État** : le mode (`'light' | 'dark'`, défaut `'light'`) et la marque
  (`'brand1' | 'brand2' | 'brand3'`, défaut `'brand1'`).
- **Effet** : `dark` pose `[data-theme='dark']`, `light` retire l'attribut (les sémantiques de
  `:root` s'appliquent). `brand1` retire `data-brand`, `brand2` / `brand3` le posent, ce qui
  redéfinit les `--primitives-*` et se propage aux sémantiques qui les référencent.
- **Persistance** : les deux choix sont mémorisés dans `localStorage` (clés `ui-kit-theme` et
  `ui-kit-brand`) et suivis d'un onglet à l'autre. `persist={false}` coupe la mémorisation,
  pour un projet qui porte déjà la sienne (profil utilisateur, cookie).

### Lire et changer le mode : `useUiTheme`

```tsx
import { useUiTheme } from '@4sh/ui-kit-react/theming';

const { theme, setTheme, toggleTheme } = useUiTheme();

toggleTheme();       // light ⇄ dark, mémorisé
setTheme('dark');
const dark = theme === 'dark';
```

### Lire et changer la marque : `useUiBrand`

```tsx
import { useUiBrand } from '@4sh/ui-kit-react/theming';

const { brand, setBrand } = useUiBrand();

setBrand('brand2');  // active la palette de la marque 2
```

Les deux crochets lèvent une erreur explicite hors de `<UiThemeProvider>`.

### Une valeur imposée par le projet

Le fournisseur suit la convention contrôlé / non contrôlé du kit. `defaultTheme` et
`defaultBrand` fixent la valeur de départ ; `theme` et `brand` la **contrôlent**, et
`onThemeChange` / `onBrandChange` annoncent les demandes de changement. C'est la voie d'une
marque qui dérive du sous-domaine (multi-tenant) ou d'un mode stocké côté serveur :

```tsx
const brand = brandFromHostname(window.location.hostname); // votre règle

<UiThemeProvider brand={brand}>
  <App />
</UiThemeProvider>
```

### Rendu serveur

Le fournisseur ne s'exécute qu'après l'hydratation : une page rendue côté serveur
s'afficherait en clair avant de basculer. `uiThemeBootstrapScript()` renvoie un script à
injecter dans le `<head>`, qui pose le mode et la marque mémorisés **avant la première
peinture**.

### Un sous-arbre dans un autre mode

Les jetons répondent aussi aux classes `.light` / `.dark` et `.brand2` / `.brand3`, et
`[data-theme='light']` rétablit le clair sous un ancêtre sombre. Pour forcer un mode ou une
marque sur une zone (un aperçu, un bandeau), posez-y `data-theme` **même en clair**, avec
`data-brand` au besoin : c'est lui qui redéclare les jetons sémantiques sur la zone, et leur
fait donc relire les primitives de la marque posée. Une marque seule n'atteindrait que les
`--primitives-*`. C'est ce que fait l'explorateur **Foundations → Colors**.

## Hooks de composant (`--ui-*`)

Les tokens règlent le système ; les **hooks** règlent un composant. Chaque valeur
structurelle d'un composant (hauteur, inset, rayon, épaisseur de bordure, taille de police…)
est lue à travers une custom property dont le défaut est le réglage livré :

```scss
// dans ui-button.scss
height: var(--ui-button-height-small, var(--size-components-sm));
//          ↑ le hook                    ↑ le défaut livré
```

Le composant ne **déclare** jamais ce nom : il ne fait que le lire. Le poser n'importe où
au-dessus suffit donc, et la portée se choisit par le sélecteur :

```scss
:root               { --ui-button-height-small: 24px; }  /* tous les boutons small */
.toolbar .ui-button { --ui-button-height-small: 24px; }  /* cette zone seulement */
```

C'est le **seul levier disponible en mode paquet**, où le SCSS du kit est déjà compilé.
Le mode copie (`@4sh/ui-kit-react-cli`, en construction) mettra le code des composants dans
le projet : leurs variables SCSS y seront rebindables directement (voir
**Components → configuration**).

### Deux réflexes

- **Une couleur** se retouche par son token sémantique (`--actions-high-surface-default`),
  pas par un hook : le token suit la marque, le clair/sombre, et son contraste est vérifié.
  Les rares hooks de couleur servent à repeindre **un exemplaire** (voile de masque,
  marqueur de chargement, reflet de squelette).
- **Une valeur partagée par tout le kit** (espacement, rayon, taille de contrôle) se
  retouche par son token `--units-*` / `--radius-*` / `--size-components-*` : inutile de
  poser quarante hooks pour un même effet.

**Tous les hooks réglables** y sont déclarés à leur valeur livrée, groupés par catégorie →
composant → type de propriété (dimensions, espacements, bordures, typographie, couleurs),
valeurs alignées. Leur nombre est donné en tête du fichier.

On le copie dans un dossier **`presets/`** du projet et on l'importe depuis la feuille globale,
elle-même importée par le point d'entrée après `@4sh/ui-kit-react/styles.css` :

```
src/styles/
├── main.scss
└── presets/
    ├── component-vars.scss   ← le fichier livré, valeurs retouchées
    └── compact.scss          ← ou un préréglage nommé, à côté
```

```scss
// src/styles/main.scss
@use 'presets/component-vars';
```

Tel quel, le fichier livré ne change rien : il redéclare les défauts. **L'ordre de
chargement n'a pas d'importance** : le kit ne *déclare* jamais ces noms, il ne fait que
les lire. (Une surcharge de **token**, elle, doit venir après `styles.css`, puisque le
kit y déclare déjà les tokens.)

> Un préréglage n'a pas besoin d'être exhaustif : seules les lignes présentes s'appliquent,
> le reste garde le défaut du kit.

Il est aussi livré dans le package (`@4sh/ui-kit-react/styles/component-vars.scss`) et **généré**
depuis les `.scss` du kit, valeurs lues dans le CSS compilé : il ne peut pas dériver du
code.

> Le hook de chaque valeur est indiqué dans la colonne **« Hook exposé »** de la section
> « Theming » de chaque composant. Les hooks absents du fichier (valeur dépendante de la
> variante rendue, ou propriété que le composant se pose lui-même) y figurent aussi, avec
> leur rôle.
