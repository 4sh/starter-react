# Getting started

Deux façons de consommer ce Design System : le choix se fait une fois, au démarrage du
projet. La première est disponible, la seconde est en construction.

<div className="sb-callout">

**Rien n'est publié à ce jour.** Les trois paquets portent `private: true` en attendant leur
première release, et le nom `@4sh/ui-kit-react` n'est pas encore réservé sur npm : il peut
donc changer d'ici là. En attendant, le kit se consomme depuis le dépôt, par un lien
d'espace de travail (`workspace:*`), ce que fait déjà l'application de démonstration. Les
détails de la publication visée sont dans `docs/PUBLISHING.md`.

</div>

<br />

## Paquet : `pnpm add @4sh/ui-kit-react`

Les composants sont publiés sous forme d'**un seul paquet npm**, consommable par n'importe
quelle application React 19.

```bash
pnpm add @4sh/ui-kit-react
```

<div className="sb-callout">

**Le gestionnaire de paquets est libre.** Le paquet est un tarball npm standard :
`npm install` ou `yarn add` installent la même chose. `pnpm` est celui que le Design System
utilise et recommande : sa résolution stricte fait échouer une `peerDependency` manquante au
lieu de la masquer, et ses réglages de chaîne de dépendances mettent en quarantaine les
versions publiées depuis moins de 24 h.

</div>

<div className="sb-callout">

**Pas de risque d'oubli d'installation.** `@4sh/ui-kit-react` est un **paquet unique** avec
des sous-chemins d'entrée, et non une collection de paquets séparés. Tous sont présents dès
l'installation, et les dépendances entre eux se résolvent seules : importer `UiDatepicker`
tire ce dont il a besoin, son socle de formulaire et ses icônes, sans que vous ayez quoi que
ce soit à déclarer. Le kit lui-même n'a que **deux dépendances runtime**, un positionneur et
un virtualiseur, chacune importée par un seul fichier (décision D6).

</div>

### Deux gestes, une fois pour toutes

```tsx
// La fondation : les jetons (3 marques × clair/sombre × responsive), la couche de base et
// les classes utilitaires. Sans elle, les composants rendent sans style.
import '@4sh/ui-kit-react/styles.css';

// Le mode et la marque actifs, posés sur <html>, qui est ce que les jetons attendent.
import { UiThemeProvider } from '@4sh/ui-kit-react/theming';

export function App({ children }) {
  return <UiThemeProvider>{children}</UiThemeProvider>;
}
```

Ensuite, la CSS d'un composant voyage avec lui : l'importer suffit.

```tsx
import { UiDatepicker } from '@4sh/ui-kit-react/ui-datepicker';

export function Booking() {
  const [date, setDate] = useState(null);

  return <UiDatepicker label="Date" valueType="date" value={date} onValueChange={setDate} />;
}
```

<div className="sb-callout">

⚠️ **La catégorie ne fait pas partie du chemin d'import** : `@4sh/ui-kit-react/ui-datepicker`,
jamais `@4sh/ui-kit-react/forms/ui-datepicker`. Elle ne regroupe que des fichiers dans le
dépôt, donc déplacer un composant d'une famille à l'autre n'est jamais une rupture pour vous
(décision D4).

</div>

Le nom du sous-chemin est celui du composant : la page de doc de chaque composant, dans la
barre latérale, donne l'import exact à recopier.

### Rendu serveur

Tout composant interactif porte `'use client'`, conservé par la construction du paquet : il
fonctionne tel quel sous l'App Router de Next. Pour éviter le passage du clair au sombre à la
première image, injectez `uiThemeBootstrapScript()` dans le `<head>` : il applique le mode
mémorisé avant la première peinture, ce que le fournisseur ne peut pas faire puisqu'il ne
s'exécute qu'après.

<br />
<br />

## Mode copie : `@4sh/ui-kit-react-cli`

L'installation livre les composants **construits**. Le second mode de consommation les
installe en **sources**, dans votre dépôt, libres d'être modifiées, à la façon de shadcn :
poser la fondation, copier les composants choisis, puis proposer leur mise à jour par
comparaison après une release du kit.

<div className="sb-callout">

**En construction (phase 4).** Le paquet `@4sh/ui-kit-react-cli` est réservé dans l'espace
de travail mais n'a pas encore de code. Tant qu'il n'existe pas, le mode paquet est le seul
disponible. L'état d'avancement se lit dans `docs/ROADMAP.md`.

</div>

<br />
<br />

## MCP : `@4sh/ui-kit-react-mcp`

Un serveur MCP compagnon, pour qu'un agent de codage interroge le catalogue et la doc du kit
sans lire les sources.

<div className="sb-callout">

**En construction (phase 5).** Le paquet `@4sh/ui-kit-react-mcp` est lui aussi réservé et
vide. En attendant, un agent travaille très bien avec `AGENTS.md` à la racine du dépôt, qui
décrit les conventions du kit, et avec les pages de ce Storybook.

</div>

<br />
<br />
