# Dual-Engine : ce qui doit rester identique entre les stacks

Le Design System a deux implémentations, une par stack : `starter-angular` et ce dépôt.
Elles ne partagent aucun code. Ce qu'elles partagent, c'est un **contrat**, et rien dans
l'outillage ne l'impose automatiquement pour l'instant. Ce fichier est la liste de ce qui
doit être vérifié à la main, et le cahier des charges du contrôle qui l'automatisera.

## Les invariants

| Invariant                   | Pourquoi il compte                                                                                          |
| --------------------------- | ----------------------------------------------------------------------------------------------------------- |
| **Nom du composant**        | `ui-button` des deux côtés. C'est la clé qui relie une story, une page Figma et une entrée MCP.             |
| **Valeurs des jetons**      | `design-tokens/*.json` est la même donnée dupliquée (décision D2). Une divergence casse la parité visuelle. |
| **Noms de classes CSS**     | `.ui-button`, `._high`, `._small`. Un projet qui migre d'un stack à l'autre garde ses surcharges.           |
| **Noms des hooks `--ui-*`** | Le thème d'un projet (`component-vars.scss`) doit s'appliquer aux deux stacks sans réécriture.              |
| **`node-id` Figma**         | Un seul composant Figma par composant du DS, référencé par les deux stories.                                |
| **Sémantique des props**    | Les noms peuvent différer (`ngModel` → `value`), le sens jamais.                                            |
| **Titre dans Storybook**    | `Components/ui/<catégorie>/ui-<nom>` : la doc des deux stacks se lit au même endroit.                       |

## Ce qui a le droit de diverger

- **Le chemin d'import.** Plat ici (`@4sh/ui-kit-react/ui-button`), catégorisé côté
  Angular : c'est une contrainte de `ng-packagr` qu'on n'a pas reproduite (décision D4).
- **La forme des props.** Signals et `ControlValueAccessor` d'un côté, contrôlé/non
  contrôlé et `ref` de l'autre. C'est la frontière du stack, pas du Design System.
- **La projection de contenu.** `TemplateRef` et `ng-content` contre `children`,
  `ReactNode` et `render*`.
- **La couche de comportement.** Angular CDK d'un côté, implémentation interne de
  l'autre (décision D6). C'est justement pour que cette divergence reste _de forme_ et non
  _de comportement_ que le kit React n'a pas pris de librairie de composants : les deux
  stacks écrivent contre la même spécification, qui est le code Angular.

## Divergences déclarées

Une divergence écrite est un choix ; une divergence découverte est un bug. Celles-ci sont
volontaires, et chacune porte sa raison.

| Sujet                                                           | Divergence                                                                                                                                                                                                                                                                                                                                                                                                                             | Pourquoi                                                                                                                                                                                                                                                                                                                                                                                                                             |
| --------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `ui-radio` · `aria-invalid`                                     | Angular le pose, React **non**.                                                                                                                                                                                                                                                                                                                                                                                                        | La spécification ARIA ne le supporte pas sur le rôle `radio`, et c'est cohérent : la validité porte sur le choix, donc sur le groupe. Signalé par `jsx-a11y`. **À corriger côté Angular.**                                                                                                                                                                                                                                           |
| `ui-radio` · règle CSS de l'état coché                          | React ajoute `&-input:checked + &-box &-dot` à côté de `._checked`.                                                                                                                                                                                                                                                                                                                                                                    | React a un mode **non contrôlé** qu'Angular n'a pas : un bouton radio ne peut pas observer la désélection de ses voisins, donc aucune classe calculée ne peut être juste. Le sélecteur natif, lui, l'est toujours. Additif : le comportement contrôlé est inchangé.                                                                                                                                                                  |
| `ui-toggle` · `aria-checked`                                    | Angular le pose, React **non**.                                                                                                                                                                                                                                                                                                                                                                                                        | Sur un `<input type="checkbox">`, l'état coché natif est déjà exposé quel que soit le `role`. Un doublon qui peut diverger de l'état réel donne un comportement indéfini.                                                                                                                                                                                                                                                            |
| `ui-progress-bar` · `valuePosition="bottom"`                    | React aligne la piste en `stretch`, Angular en `flex-end`.                                                                                                                                                                                                                                                                                                                                                                             | En colonne, `align-items` gouverne l'axe horizontal : le `flex-end` ramenait la piste à sa largeur de contenu, soit **zéro**, et la barre disparaissait. Mesuré ici, la SCSS étant reprise à l'octet près. React étire la piste et n'aligne à droite que le libellé, ce qui garde l'intention d'origine. **À corriger côté Angular.**                                                                                                |
| `ui-modal` · structure et empilement                            | React rend un `<dialog>` **natif** ; Angular reconstruit un scrim, un positionneur et un piège de focus CDK. React n'expose donc **ni `autoZIndex` ni `baseZIndex`**.                                                                                                                                                                                                                                                                  | Le calque supérieur empile les dialogues dans leur ordre d'ouverture, sans z-index : garder ces deux props serait promettre un réglage sans effet. Le piège de focus, la restitution du focus, l'inertie du fond et Échap sont également natifs. Le DOM diverge, l'API publique et le rendu visuel non. Mesuré avant d'être décidé, voir « Spécifications / Couches et focus ».                                                      |
| `ui-popover` · pilotage                                         | Angular s'appelle par des **méthodes** (`show`, `hide`, `toggle`) et pose lui-même `aria-expanded` sur le déclencheur ; React est **contrôlé** (`open` / `defaultOpen` / `onOpenChange`) et rend le déclencheur par `trigger`.                                                                                                                                                                                                         | Muter le DOM d'un élément que React possède est un anti-motif : l'attribut serait réécrit au rendu suivant. La prop de rendu donne le même service en restant dans le modèle du framework, et aligne le composant sur le contrat contrôlé du reste du kit.                                                                                                                                                                           |
| `ui-tooltip` · forme et props                                   | Angular est une **directive** (`[uiTooltip]`) ; React est un composant à `trigger`. React n'expose **ni `escape` ni `tooltipContext`**.                                                                                                                                                                                                                                                                                                | React n'a pas de directives. `escape={false}` liait du HTML brut : `content` accepte n'importe quel nœud, ce qui couvre le besoin sans jamais injecter de HTML, et respecte l'interdiction de `dangerouslySetInnerHTML`. `tooltipContext` n'a plus d'objet, une fermeture faisant le travail d'un contexte de gabarit.                                                                                                               |
| `ui-popover` et `ui-tooltip` · calque                           | React place les panneaux dans le **calque supérieur** (`popover`, ou `<dialog>` en modal) ; Angular les monte dans un overlay CDK.                                                                                                                                                                                                                                                                                                     | Mesuré : le panneau échappe alors au rognage d'un ancêtre en `overflow: hidden` sans z-index (vérifié à 320 px de large dans un cadre de 220 px), et `popover="auto"` donne la fermeture au clic extérieur sans une ligne de JavaScript.                                                                                                                                                                                             |
| `ui-select` · chevron en mode éditable                          | React rend un **bouton** nommé (`ui-select-toggle`, mixin `field-action`) ; Angular rend une icône décorative dont le clic est capté par une enveloppe.                                                                                                                                                                                                                                                                                | En mode éditable, le chevron est la SEULE façon d'ouvrir le panneau à la souris : il doit donc exister au clavier. La version Angular n'y est pas atteignable. C'est `jsx-a11y` qui a signalé le clic sur un élément non interactif, et le corriger a amélioré le composant plutôt que de le contourner. **À corriger côté Angular.**                                                                                                |
| `ui-chip` · priorité du `role`                                  | React laisse GAGNER un `role` fourni par l'appelant ; Angular garde le sien.                                                                                                                                                                                                                                                                                                                                                           | Côté Angular, l'hôte `<ui-chip>` et le span interne sont deux éléments, donc les deux rôles cohabitent. Ici c'est le même élément : sans cette priorité, une puce servant d'`option` dans `ui-autocomplete` verrait son rôle remplacé par `group`, et la liste perdrait ses options. Additif : sans `role` fourni, rien ne change.                                                                                                   |
| `utils.field-action` · géométrie                                | React annule l'inset vertical du champ `_auto-height` et donne une largeur explicite ; Angular garde `aspect-ratio: 1` sans annulation.                                                                                                                                                                                                                                                                                                | Mesuré : l'action s'arrêtait à la boîte de contenu (32 px pour une boîte de 40), et sa largeur retombait à celle de l'icône (20 px), **sous le minimum de cible de WCAG 2.5.8**. Visible sur tout champ `_auto-height` portant une action (`ui-input-tags`, `ui-select` et `ui-autocomplete` en multiple). **À corriger côté Angular.**                                                                                              |
| `ui-menu` · pilotage du popup                                   | Angular s'appelle par des **méthodes** (`toggle(event)`, `show`, `hide`) et expose un `uid` pour que le déclencheur y branche son `aria-controls` ; React est **contrôlé** (`open` / `defaultOpen` / `onOpenChange`) et rend le déclencheur par `trigger`, qui reçoit `aria-haspopup`, `aria-expanded` et `aria-controls` tout faits.                                                                                                  | Même arbitrage que `ui-popover`, et pour la même raison : le kit React ne mute pas le DOM d'un élément que React possède. La prop de rendu donne le même service en restant dans le modèle du framework.                                                                                                                                                                                                                             |
| `ui-menu` · liens et route active                               | Angular a `routerLink`, `queryParams`, `queryParamsHandling` et `routerLinkActive` ; React a `render` sur l'item, plus `active`.                                                                                                                                                                                                                                                                                                       | Le kit n'impose aucun routeur, comme sur `ui-button` et `ui-link` : `render` reçoit les props que le menu aurait posées sur son `<a>`. Et l'appelant est le seul à savoir si l'entrée est celle de la page courante, d'où `active` en remplacement d'une directive de routeur.                                                                                                                                                       |
| `ui-menu` · prop `tabindex`                                     | Angular expose le `tabindex` de l'arrêt de tabulation ; React **non**.                                                                                                                                                                                                                                                                                                                                                                 | En React, `...rest` transmet déjà `tabIndex` au panneau : une prop du même nom qui atterrirait sur une entrée serait un piège. L'arrêt de tabulation reste à 0, ce qui est le motif menu de l'APG.                                                                                                                                                                                                                                   |
| `ui-menu` · calque et mouvement                                 | React place le popup et les sous-menus en cascade dans le **calque supérieur** (`popover="manual"`) et anime l'entrée et la sortie en CSS pur ; Angular les monte dans un overlay CDK et pilote le mouvement par une directive.                                                                                                                                                                                                        | Même mesure que pour `ui-popover` et `ui-tooltip` : plus de z-index, plus de rognage par un ancêtre en `overflow: hidden`, et une sortie animée sans garder soi-même le nœud dans le DOM. **Un `popover="manual"` ne restitue pas le focus** en se fermant, contrairement à `auto` : mesuré, et le composant s'en charge donc explicitement.                                                                                         |
| `ui-context-menu` · pilotage                                    | Angular expose `show(event)`, `hide()` et `toggle(event)` ; React se gouverne seul, avec `onOpen` et `onClose` pour observer.                                                                                                                                                                                                                                                                                                          | Un menu contextuel n'a pas d'état utile sans les coordonnées qui vont avec, et l'événement d'ouverture porte les deux à la fois. Un panneau ouvert par programme est `ui-menu` en mode `popup`, qui est contrôlé. Aucune poignée impérative dans le kit React.                                                                                                                                                                       |
| `ui-table` · comportements de colonne                           | Angular attache par **directives** (`uiSortableColumn`, `uiSelectableRow`, `uiFrozenColumn`, `uiResizableColumn`, `uiRowToggler`, `uiReorderableRow`) ; React passe des **fabriques de props** au balisage projeté, plus un contexte pour les contrôles.                                                                                                                                                                               | React n'a pas de directives, et un crochet ne convient pas non plus : une ligne se rend dans une boucle dont la longueur varie, et un crochet appelé un nombre variable de fois est interdit. Une fabrique de props est sans état, donc sûre dans une boucle, et rend exactement ce qu'une directive posait sur l'hôte.                                                                                                              |
| `ui-table` · colonnes figées                                    | Angular a une directive et un `ResizeObserver` par cellule ; React calcule les décalages une fois par ligne, au même endroit que ses autres mesures.                                                                                                                                                                                                                                                                                   | Le tableau voit la ligne entière, donc il n'a rien de plus à observer, et une colonne figée n'est plus qu'une classe côté appelant. Moins de code pour le même rendu.                                                                                                                                                                                                                                                                |
| `ui-table` · poignée de redimensionnement                       | Angular l'**injecte dans le DOM** depuis sa directive ; React la rend, `<UiTableColumnResizer />`.                                                                                                                                                                                                                                                                                                                                     | React possède le balisage : y injecter un nœud serait écrasé au rendu suivant. Même arbitrage que sur `ui-popover`, qui ne mute pas le DOM de son déclencheur.                                                                                                                                                                                                                                                                       |
| `ui-table` · état de tri                                        | Angular a trois entrées (`sortField`, `sortOrder`, `multiSortMeta`) ; React a une valeur contrôlable, `sort`.                                                                                                                                                                                                                                                                                                                          | Le tri EST une chose, et le découpage n'était gratuit que grâce aux signaux. Une valeur unique se branche sur le contrat contrôlé du kit, et `onSortChange` porte le mode, ce dont un appelant en mode serveur a besoin.                                                                                                                                                                                                             |
| `ui-table` · zone défilante et clavier                          | Angular pose `tabindex` dès que `scrollable` ; React ne le pose que si la zone déborde **et** ne contient rien de focalisable.                                                                                                                                                                                                                                                                                                         | axe exige qu'une région défilante soit atteignable, mais un arrêt de tabulation sur une zone dont le contenu l'est déjà n'encombre que le parcours clavier. Même contrat que `ui-modal`. **À corriger côté Angular.**                                                                                                                                                                                                                |
| `ui-table` · encapsulation                                      | Angular doit sortir de l'encapsulation (`ViewEncapsulation.None`) pour que ses styles atteignent le balisage projeté ; React n'a rien à désactiver.                                                                                                                                                                                                                                                                                    | Le kit React n'a pas d'encapsulation : le préfixe `ui-` EST le namespace (décision D5). Ce que la version Angular obtient par une dérogation est ici l'état normal.                                                                                                                                                                                                                                                                  |
| `ui-menu` · clic sur un parent de cascade                       | Angular **bascule** le sous-menu au clic ; React l'**ouvre**, sans le refermer.                                                                                                                                                                                                                                                                                                                                                        | À la souris, le survol a déjà ouvert le panneau avant que le clic arrive : une bascule le referme donc aussitôt, et cliquer un parent paraît sans effet. Le défaut est présent à l'identique côté Angular, la forme du code y étant la même. **À corriger côté Angular.**                                                                                                                                                            |
| `ui-menu` · survol après une activation                         | React ignore un `mouseenter` qui n'a pas été précédé d'un `pointermove` ; Angular le traite.                                                                                                                                                                                                                                                                                                                                           | Masquer un panneau change l'élément sous le pointeur, et le navigateur émet alors un `mouseenter` sans que l'utilisateur ait bougé. Mesuré : 7 ms après la fermeture d'un sous-menu, son parent en reçoit un et le rouvre. Même code côté Angular, donc même défaut. **À corriger côté Angular.**                                                                                                                                    |
| `ui-context-menu` · cible                                       | Angular prend un `target` (élément ou `ElementRef`) ou `global` ; React rend la zone par `trigger` et lui passe la `ref`, ou prend `global`.                                                                                                                                                                                                                                                                                           | Une prop de rendu remplace la variable de référence de template, comme sur `ui-tooltip`, qui était une directive. Le composant ne va pas chercher un élément qu'il ne rend pas.                                                                                                                                                                                                                                                      |
| `core/motion` · forme de la brique                              | Angular est une **directive** (`uiMotion`) qui donne des noms de classes à `animate.enter` / `animate.leave` ; React est un crochet, `useUiMotion`, qui retient lui-même le nœud sortant.                                                                                                                                                                                                                                              | React n'a pas de directives, et surtout pas d'équivalent d'`animate.leave` : un élément quitte le DOM dès que l'appelant cesse de le rendre. Le crochet rend donc `present`, vrai pendant toute la sortie. Les classes, les préréglages et les keyframes, eux, sont les MÊMES des deux côtés : c'est la partie qui compte pour la parité visuelle.                                                                                   |
| `ui-avatar-group` · portée des styles                           | Angular sort de l'encapsulation (`ViewEncapsulation.None`) pour viser l'élément `ui-avatar` projeté ; React vise la CLASSE `.ui-avatar`.                                                                                                                                                                                                                                                                                               | Le kit React n'a pas d'encapsulation, le préfixe `ui-` ÉTANT le namespace (décision D5), et les sélecteurs d'élément nu y sont interdits parce qu'ils fuiraient sur toute la page. Ce qu'Angular obtient par dérogation est ici l'état normal.                                                                                                                                                                                       |
| `ui-input-group` · reformage des items                          | Angular écrit des styles EN LIGNE sur chaque item depuis un `MutationObserver` ; React le fait en CSS pur, par un sélecteur d'enfant.                                                                                                                                                                                                                                                                                                  | Même raison : un sélecteur scopé ne peut pas atteindre du contenu projeté côté Angular, d'où l'observateur. Ici le sélecteur passe, donc le composant n'a plus aucun JavaScript, et il suit les `@if`/`@for` de l'appelant sans rien observer.                                                                                                                                                                                       |
| `ui-button-split` · nom du modèle                               | Angular l'appelle `model` ; React l'appelle `items`.                                                                                                                                                                                                                                                                                                                                                                                   | Le `ui-menu` React nomme déjà ses entrées `items`, et c'est le MÊME type qui circule. Deux noms pour la même donnée dans le même kit coûterait plus cher que l'écart avec Angular, que la règle « le sens jamais » autorise explicitement.                                                                                                                                                                                           |
| `ui-button-split` · pilotage et poignées                        | Angular expose `tabindex`, `buttonProps`, `focus()` et `hide()`, plus `menuShow` / `menuHide` ; React expose `open` / `defaultOpen` / `onOpenChange` et rien d'impératif.                                                                                                                                                                                                                                                              | Mêmes arbitrages que `ui-popover` et `ui-menu`, dont ce composant n'est qu'un assemblage : `...rest` remplace `buttonProps`, aucune poignée impérative dans le kit React, et `onOpenChange` dit à lui seul ce que disaient `menuShow` et `menuHide`.                                                                                                                                                                                 |
| `ui-tabs` · élément hôte de l'onglet                            | Angular a un hôte `ui-tab` en `display: contents` autour d'un `.ui-tab-button` ; React rend le bouton seul, et `.ui-tab` EST ce bouton.                                                                                                                                                                                                                                                                                                | React ne rend pas d'élément hôte : les règles qui vivaient sur `:host` se fondent dans la classe racine, comme partout ailleurs dans ce kit (décision D5). `.ui-tab-button` n'a donc plus d'élément à décrire. Les sous-éléments `.ui-tab-icon` et `.ui-tab-label` sont inchangés.                                                                                                                                                   |
| `ui-tabs` · prop `tabindex`                                     | Angular expose le `tabindex` de l'arrêt de tabulation ; React **non**.                                                                                                                                                                                                                                                                                                                                                                 | Même arbitrage que sur `ui-menu` : `...rest` transmet déjà `tabIndex` à la racine, donc une prop du même nom qui atterrirait sur un onglet serait un piège. L'arrêt reste à 0, ce qui est le motif Tabs de l'APG.                                                                                                                                                                                                                    |
| `ui-tabs` · panneau focalisable                                 | Angular pose `tabindex="0"` sur tout panneau ; React ne le garde que si le panneau ne contient rien de focalisable.                                                                                                                                                                                                                                                                                                                    | C'est ce que dit le motif Tabs de l'APG, et le même contrat que `ui-table` et `ui-modal` appliquent déjà ici : un arrêt de tabulation devant un contenu déjà atteignable n'encombre que le parcours clavier. **À corriger côté Angular.**                                                                                                                                                                                            |
| `ui-tabs` · valeur « aucun onglet actif »                       | Angular l'écrit `undefined` ; React l'écrit `null`.                                                                                                                                                                                                                                                                                                                                                                                    | Le contrat contrôlé du kit lit `value === undefined` comme « non contrôlé » : sans ce partage, un conteneur contrôlé sans sélection basculerait en non contrôlé. Même choix que `ui-segment-control`, dont la valeur vide est déjà `null`.                                                                                                                                                                                           |
| `ui-tabs` · hooks d'indicateur hérités                          | Angular honore encore `--ui-tabs-active-bar-color` et `-size` en repli ; React ne connaît que `--ui-tabs-indicator-*`.                                                                                                                                                                                                                                                                                                                 | Ce sont les noms d'AVANT le renommage côté Angular, gardés une version pour ses consommateurs. Ce dépôt n'a jamais publié les anciens : les replier ici serait promettre une compatibilité avec un passé qu'il n'a pas.                                                                                                                                                                                                              |
| `ui-accordion` · en-tête                                        | Angular a un slot `uiAccordionHeader` **en plus** d'une entrée texte `header`, et un marqueur `uiAccordionContent` ; React n'a qu'une prop `header` de type `ReactNode`.                                                                                                                                                                                                                                                               | Une prop `ReactNode` couvre le titre texte et l'en-tête riche du même coup : le slot n'a plus d'objet, et le corps est déjà `children`. React n'a pas de directives, donc pas de marqueur non plus.                                                                                                                                                                                                                                  |
| `ui-accordion` · valeur « rien d'ouvert »                       | Angular l'écrit `undefined` ; React l'écrit `null`.                                                                                                                                                                                                                                                                                                                                                                                    | Même arbitrage que `ui-tabs` : dans le contrat contrôlé du kit, `undefined` veut dire « non contrôlé ». Les deux sens ne peuvent pas partager une valeur.                                                                                                                                                                                                                                                                            |
| `ui-accordion` · sorties et poignée                             | Angular a `opened` / `closed` et une méthode `focus()` sur le panneau ; React a `onPanelOpen` / `onPanelClose` et **aucune** poignée impérative.                                                                                                                                                                                                                                                                                       | Le préfixe `on` est la convention de sortie du kit, et le clavier du groupe déplace lui-même le focus : une poignée publique n'aurait aucun appelant. Aucune API impérative dans le kit React, comme sur `ui-popover` et `ui-menu`.                                                                                                                                                                                                  |
| `ui-toast` · forme du magasin                                   | Angular injecte un service `UiToastService` (`providedIn: 'root'`) ; React exporte un singleton de module, `uiToast`, plus le crochet de lecture `useUiToasts`.                                                                                                                                                                                                                                                                        | Une notification se déclenche aussi depuis un intercepteur HTTP ou un gestionnaire d'erreurs, c'est-à-dire hors de tout composant. Un contexte obligerait à poser un fournisseur à la racine et resterait inatteignable de là ; un module rend le même service sans rien imposer.                                                                                                                                                    |
| `ui-toast` · routage des messages                               | Angular l'appelle `key`, sur le conteneur comme sur le message ; React l'appelle `channel`.                                                                                                                                                                                                                                                                                                                                            | `key` est **réservé** par React pour l'identité d'un élément : une prop de ce nom n'atteindrait jamais le composant. Renommé des deux côtés du contrat pour que le message et la pile parlent pareil.                                                                                                                                                                                                                                |
| `ui-toast` · contenu sur mesure                                 | Angular passe un `TemplateRef` par l'entrée `template` ; React passe `renderToast(message, { close })`.                                                                                                                                                                                                                                                                                                                                | React n'a pas de `TemplateRef`, et le kit prend une prop de rendu pour tout slot paramétré. Le contexte `$implicit` / `closeFn` devient les deux arguments.                                                                                                                                                                                                                                                                          |
| `ui-toast` · calque et empilement                               | Angular pose la pile en `fixed` à un z-index, et expose `autoZIndex` et `baseZIndex` ; React la place dans le **calque supérieur** (`popover="manual"`) et n'expose ni l'un ni l'autre.                                                                                                                                                                                                                                                | Mesuré : `ui-modal` est ici un `<dialog>` **natif**, donc dans ce calque, et aucun z-index ne passe devant. La pile s'y remontre à chaque nouveau message, le calque empilant dans l'ordre d'affichage. Garder les deux props serait promettre un réglage sans effet, comme sur `ui-modal`. `contained` reste en z-index.                                                                                                            |
| `ui-toast` · compte à rebours d'une file                        | Angular arme le délai **à l'arrivée**, même pour un message au-delà de `stackVisibleLimit` ; React l'arme **quand la carte paraît**.                                                                                                                                                                                                                                                                                                   | Côté Angular un message en file expire sans avoir jamais été affiché, ce que sa propre doc ne décrit pas (« les autres attendent leur tour »). Ici il attend vraiment son tour. **À corriger côté Angular.**                                                                                                                                                                                                                         |
| `ui-toast` · pointeur de la bande                               | Angular rend le pointeur à la **bande** qui porte chaque carte ; React le rend à la **carte**.                                                                                                                                                                                                                                                                                                                                         | Mesuré : la bande fait toute la largeur de la pile alors que la carte fait sa largeur de contenu. Elle avale donc les clics de la page à côté de la carte, et suspend le compte à rebours dès que le pointeur passe sur la même ligne. Même piège que sur `ui-tooltip`. **À corriger côté Angular.**                                                                                                                                 |

## Reporter une évolution de jeton

Les jetons sont dupliqués par décision. La procédure, jusqu'à ce que le contrôle
automatique existe :

1. Éditer `design-tokens/*.json` dans le dépôt où le besoin apparaît.
2. `pnpm tokens:build`, vérifier dans Storybook `Foundations / Colors`.
3. **Reporter le même diff JSON dans l'autre dépôt**, et le mentionner dans les deux
   CHANGELOG.
4. Si le jeton est nouveau, il doit aussi exister dans Figma (fichier
   `lH4jhyZFkIeJ1Ob1tlY7Wm`, propriétaire des collections).

## À construire : `scripts/parity.check.mjs`

Le contrôle qui rendrait cette page exécutable au lieu d'être une consigne. Il comparerait
les deux manifestes `storybook/generated/ui-config.json` et signalerait :

- un composant présent d'un seul côté (attendu pendant la construction, mais il doit être
  **listé** comme tel, pas découvert) ;
- un hook `--ui-*` présent d'un seul côté ;
- un jeton dont la valeur diffère entre les deux `design-tokens/` ;
- un `node-id` Figma qui diffère pour le même composant.

Il tournerait dans les deux CI, en lisant le manifeste de l'autre dépôt publié sur Pages.
Phase 6.
