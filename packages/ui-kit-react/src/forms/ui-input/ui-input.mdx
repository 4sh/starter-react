# ui-input

Champ texte composé : la coquille `ui-field` plus un `<input>` natif. Couvre tous les types
texte, mot de passe compris.

## Contrôlé ou non contrôlé

C'est le contrat le plus important du composant, et il est le même pour **tous** les champs
du kit.

<Canvas of={InputStories.Controlled} />

C'est ce qui rend l'interopérabilité gratuite. `<Controller>` de react-hook-form fournit
`value` et `onChange`, donc le champ est contrôlé **sans que le kit connaisse la
librairie** :

```tsx
<Controller
  name="email"
  control={control}
  render={({ field, fieldState }) => (
    <UiInput
      {...field}
      onValueChange={field.onChange}
      label="Adresse e-mail"
      invalid={fieldState.invalid}
      errorText={fieldState.error?.message}
    />
  )}
/>
```

Et un formulaire natif, sans librairie, fonctionne en non contrôlé par le `name` du champ.

## Icônes et zone d'action

`iconLeft` et `iconRight` acceptent **un nom** (rendu par `ui-icon`) ou **un nœud** rendu tel
quel.

L'icône de droite devient une **zone d'action** : un vrai `<button>` carré sur toute la
hauteur : dès qu'elle porte un `iconRightAriaLabel`. C'est le mécanisme qui sert à révéler
un mot de passe ou à vider une recherche : pas de prop dédiée, un seul chemin.

<Canvas of={InputStories.WithRightAction} />

Sans nom accessible, pas de bouton. Un bouton sans nom est un piège pour un lecteur d'écran,
pas une fonctionnalité.

## Validation

`invalid` force le rendu en erreur, et `errorText` remplace alors le texte d'aide. Le
composant pose `aria-invalid` et chaîne l'identifiant du message dans `aria-describedby` :
avec celui que vous fournissez, jamais à sa place.

## Saisie automatique du navigateur

Quand le navigateur préremplit un formulaire (adresse, e-mail, code reçu par SMS), il écrit
dans des champs où l'utilisateur n'est pas. Selon le navigateur, il annonce la valeur par un
`input`, par un `change` seul, ou par **aucun événement** : la valeur s'affiche alors sans que
React la connaisse, et le rendu suivant d'un champ contrôlé l'écrase. Les champs du kit
suivent ces trois cas : `onValueChange` est appelé **une seule fois**, sans attendre un clic
dans le champ, en mode contrôlé comme non contrôlé. La frappe et le collage ne changent pas.

Le cas sans événement passe par une animation que `styles.css` lance sur `:-webkit-autofill` :
le champ reçoit alors l'`input` que le navigateur n'a pas émis. **La feuille `styles.css` doit
donc être chargée**, ce qu'elle est déjà pour les jetons.

Une valeur écrite sans focus est traitée comme un remplissage, pas comme une frappe :

Chrome envoie aussi, à chaque champ qu'il remplit, un `focus` qui ne lui donne pas le focus.
Les comportements liés au focus l'ignorent : `showOnFocus` de `ui-datepicker`,
`completeOnFocus` de `ui-autocomplete`, la sélection d'une case de `ui-input-otp`.

Pour guider le navigateur, renseigner `autoComplete` (`name`, `email`, `tel`, `postal-code`,
`bday`…) et `name` sur le champ.

> **À prévoir côté application.** `onValueChange` (et `onOptionSelect` avec `forceSelection`)
> peut être appelé sans geste de l'utilisateur : un gestionnaire qui appelle une API ou remplit
> d'autres champs doit le tolérer. Dans les tests, un `input` envoyé à un champ sans focus vaut
> remplissage : focaliser le champ avant de simuler une frappe (`userEvent.type` ou `fill()` de
> Playwright le font déjà). Hors de portée : Chrome garde illisible par JavaScript une valeur
> qu'il préremplit au chargement de la page, jusqu'à une interaction.

### Dans un champ maison

Un champ bâti sur `@4sh/ui-kit-react/forms` obtient le même comportement : poser
`BROWSER_FILL_CLASS` sur l'élément natif et brancher `announceBrowserFill` sur son
`onAnimationStart`. `hasFocus(element)` distingue une frappe d'une valeur écrite sans focus,
par exemple pour ne pas ouvrir de panneau.

```tsx
import { BROWSER_FILL_CLASS, announceBrowserFill, hasFocus } from '@4sh/ui-kit-react/forms';

<input
  className={cx('mon-champ', BROWSER_FILL_CLASS)}
  value={text}
  onChange={(event) => {
    setText(event.target.value);
    if (hasFocus(event.target)) openPanel();
  }}
  onAnimationStart={announceBrowserFill}
/>;
```

## Theming

Le champ délègue l'essentiel de son apparence à `ui-field` : les points d'extension de la
boîte, du libellé et du message sont documentés sur la page de cette coquille. Ce qui suit
ne concerne que ce qui est propre à `ui-input`.
