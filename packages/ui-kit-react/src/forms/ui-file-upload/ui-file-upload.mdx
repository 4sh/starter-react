# ui-file-upload

Téléversement de fichiers, en champ compact (`field`) ou en zone de **glisser-déposer**
(`drag`). La sélection passe par un `<input type="file">` natif, masqué mais focalisable :
le sélecteur du système, le clavier et les lecteurs d'écran marchent nativement, et toute
la surface accepte le dépôt. Les fichiers sont validés côté client (type, taille, nombre)
puis envoyés d'eux-mêmes (`auto`), à la demande, ou par la fonction de l'application
(`customUpload`). La progression passe par `XMLHttpRequest`, sans client HTTP à fournir.

<Canvas of={FileUploadStories.Basic} />

> ℹ️ **Pas un champ contrôlé.** Contrairement aux autres champs du kit, `ui-file-upload`
> n'a ni `value` ni `onValueChange` : sa valeur (des `File` et leur état d'envoi) ne se
> sérialise pas dans un état de formulaire. On le suit par `onFilesChange`,
> `onFilesSelect`, `onUploadComplete` et `onRemove`, et on reporte le résultat (des
> identifiants, des URL) dans son formulaire. Avec `name`, la sélection part aussi avec un
> formulaire **natif**.

## Auto

Avec `auto`, un fichier part dès qu'il est choisi. Le bouton Téléverser disparaît, il n'y
a plus rien à déclencher.

<Canvas of={FileUploadStories.Auto} />

## Advanced

Glisser-déposer, plusieurs fichiers, progression, et les trois validations : `accept`,
`maxFileSize` et `fileLimit`. Un fichier refusé n'entre pas dans la liste ; le motif est
annoncé et `onUploadError` le reçoit avec sa raison (`type`, `size` ou `limit`).

<Canvas of={FileUploadStories.Advanced} />

## Envoi délégué

`customUpload` remplace l'envoi intégré par la fonction de l'application.
`onCustomUpload` reçoit les fichiers en attente et trois fonctions pour piloter leur
état : `setProgress`, `markUploaded` et `markError`.

<Canvas of={FileUploadStories.CustomUpload} />

## Envoi intégré

Sans `customUpload`, `url` suffit : chaque fichier part dans sa propre requête
multipart, sous `fieldName`. `withCredentials` est coupé par défaut, aucun cookie ne part
vers une autre origine sans le demander.

```tsx
import { UiFileUpload } from '@4sh/ui-kit-react/ui-file-upload';

<UiFileUpload
  mode="drag"
  multiple
  accept="image/*,.pdf"
  maxFileSize={5 * 1024 * 1024}
  url="/api/upload"
  aria-label="Téléverser des documents"
  onUploadComplete={({ files, xhr }) => enregistrer(files, xhr.response)}
  onUploadError={({ file, reason, message }) => signaler(file, reason, message)}
/>;
```

## Aperçu en grille

`renderContent` reçoit tous les fichiers et rend toute la section. Chaque image porte son
`objectUrl`, que le composant révoque lui-même au retrait.

## Dans un formulaire natif

Le sélecteur est vidé après chaque choix, pour qu'un nouveau choix du même fichier
redéclenche `change` : il ne peut donc rien porter jusqu'au formulaire. Avec `name`, un
second champ, caché, reçoit la sélection courante, et c'est lui que le formulaire soumet.
Désactivé, le composant ne soumet rien, comme tout champ natif.

## Composition

La liste est faite de lignes **`ui-file-upload-list`**, une par fichier : la même unité
que dans Figma. Chaque ligne passe sur `ui-spinner` pendant l'envoi. Voir
[ui-file-upload-list](?path=/docs/components-ui-forms-ui-file-upload-list--docs).
