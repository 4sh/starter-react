# ui-button-split

Un bouton d'action accolé à un déclencheur déroulant. Le bouton principal fait l'action par
défaut, celle que l'on veut la plupart du temps ; le chevron révèle les autres, décrites par
le même modèle déclaratif que [`ui-menu`](?path=/docs/components-ui-navigation-ui-menu--docs).

## API

## Les options

`items` est un `UiMenuItem[]`, exactement celui de `ui-menu` : feuilles avec `command`, `url`
ou `render`, séparateurs, icônes, groupes repliables. Rien n'est propre au bouton scindé, et
un modèle écrit pour un menu se réutilise tel quel.

## Apparence

`level`, `variant`, `onColor` et `size` s'appliquent aux **deux** boutons : les deux moitiés
sont un seul contrôle, et les voir diverger se lirait comme un défaut.

## Désactivation

`disabled` coupe tout. `buttonDisabled` et `menuButtonDisabled` coupent une moitié chacun :
c'est le cas d'une action par défaut indisponible dont les autres options restent utiles, et
l'inverse, un déclencheur vide à côté d'une action qui marche.

<Canvas of={ButtonSplitStories.Disabled} />

## Comment les deux boutons se collent

Le composant ne redéfinit aucun style de bouton. Il pose `--ui-button-radius`, le crochet que
`ui-button` expose déjà, pour carrer les deux coins intérieurs, et remonte le déclencheur
d'exactement une largeur de bordure pour que le trait partagé ne double pas. Le survolé et le
focalisé passent au-dessus de leur voisin, sans quoi leur anneau de focus serait rogné par le
recouvrement.

## Theming

Les deux boutons se thèment par les crochets de `ui-button`, le panneau par ceux de
`ui-menu`. Ce composant n'expose que le recouvrement.
