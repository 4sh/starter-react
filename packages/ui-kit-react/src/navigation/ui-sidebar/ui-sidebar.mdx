# ui-sidebar

Barre latérale applicative, en deux présentations qui partagent le même intérieur :

- **Statique** (par défaut) : la barre vit dans le flux et **pousse le contenu**. Elle se
  replie en **rail d'icônes** (`collapsed`). Avec `openOnHover`, un rail replié **flotte**
  ouvert au survol et au focus, sans décaler le contenu.
- **Superposée** : la barre **flotte** au-dessus du contenu, pilotée par `visible`. C'est un
  `<dialog>` natif, comme `ui-drawer` : piège de focus, restitution du focus, arrière-plan
  inerte, `Échap` et clic sur le voile.

## Mise en page

La barre statique s'**étire** : posez-la dans une rangée flex qui a une hauteur, à côté du
contenu. Rendue seule, son rail mesure zéro de haut, son panneau étant positionné en absolu
pour pouvoir flotter.

```tsx
import { UiSidebar, UiSidebarMenu } from '@4sh/ui-kit-react/ui-sidebar';

<div style={{ display: 'flex', height: '100dvh' }}>
  <UiSidebar aria-label="Navigation principale">
    <UiSidebarMenu items={items} aria-label="Sections" />
  </UiSidebar>
  <main style={{ flex: 1, minWidth: 0 }}>…</main>
</div>;
```

## Avec menu

En-tête et pied acceptent un nœud, ou une **fonction** qui reçoit l'état de la barre. C'est
ainsi qu'on n'affiche que l'icône dans le rail replié :

```tsx
<UiSidebar
  aria-label="Navigation"
  header={(sidebar) => (
    <>
      <UiIcon name="layer-group" size="lg" />
      {!sidebar.collapsed && <strong>App</strong>}
    </>
  )}
>
  <UiSidebarMenu items={items} tooltips aria-label="Sections" />
</UiSidebar>
```

## Adaptatif

Sous `breakpoint` (ici `1024px`, aligné sur l'échelle des points de rupture du Design System),
la barre devient un panneau superposé ; au-dessus, elle reste un rail qui pousse le contenu.
Un panneau ouvert qui repasse en statique se referme, et `onHide` le dit.

## Double barre

Un rail d'icônes permanent comme navigation primaire, accolé à une barre secondaire qui
liste les sections d'un module. Deux barres statiques côte à côte.

## Le déclencheur

Un bouton de menu vit souvent **hors** de la barre, dans la barre d'application.
`UiSidebarProvider` rend l'état de la barre lisible autour d'elle, et `useUiSidebarTrigger()`
donne les props du contrôle : `aria-controls`, `aria-expanded`, et la bascule au clic.
`Entrée` et `Espace` viennent seuls sur un `<button>`.

```tsx
import { UiSidebar, UiSidebarProvider, useUiSidebarTrigger } from '@4sh/ui-kit-react/ui-sidebar';

function MenuButton() {
  const trigger = useUiSidebarTrigger();
  return <UiButton {...trigger} icon="bars" iconOnly aria-label="Menu" />;
}

<UiSidebarProvider>
  <MenuButton />
  <UiSidebar aria-label="Navigation principale">…</UiSidebar>
</UiSidebarProvider>;
```

Un fournisseur porte **une** barre : deux barres pilotées séparément prennent chacune le
leur. Dans l'en-tête ou le pied, `getUiSidebarTriggerProps(sidebar)` donne les mêmes props à
partir de l'état reçu, sans fournisseur. `useUiSidebar()` rend l'état complet, pour un
libellé qui suit la barre.

## ui-sidebar-menu

Menu de navigation déclaratif (`UiSidebarMenuItem[]`) rendu en **région de navigation** : un
`<nav>` qui enveloppe des listes. Il gère :

- des **sections** libellées ;
- des **groupes repliables** (`toggleable`) sur plusieurs niveaux, dépliés selon
  `expandedKeys`, contrôlé ou non ;
- l'**entrée courante** (`active`), un groupe qui la contient se dépliant d'office ;
- un **badge** de fin, rendu par `ui-badge`, et l'icône « ouvre ailleurs » des liens
  externes (`external`, ou `target="_blank"`).

Posé dans une `UiSidebar`, il lit l'état replié par contexte et se replie en **rail
d'icônes**. Seul, `collapsed` pilote le rail. En rail, **`tooltips`** montre le libellé de
chaque icône en info-bulle.
