# Motion

Système d'animation piloté par les jetons, pensé pour être réutilisable par tous les
composants : ouverture d'un panneau, dépliage d'un accordéon, apparition d'un toast. Aucune
dépendance runtime, uniquement des animations et des transitions CSS natives.

## Trois primitives, et laquelle choisir

Le choix ne dépend pas de l'effet voulu mais de **ce que devient l'élément** : reste-t-il
monté, vit-il dans le calque supérieur, ou quitte-t-il le DOM ?

## useUiMotion

Le crochet rend `present`, qui reste **vrai pendant toute la sortie**. C'est là toute la
différence avec le starter Angular : là-bas `animate.leave` retient le nœud sortant, ici c'est
`present` qui le retient.

```tsx
import { useUiMotion } from '@4sh/ui-kit-react/motion';

function Panneau({ open, children }) {
  // Destructuré en tête : le résultat contient une ref de rappel, et le linter
  // des hooks refuse qu'on lise les propriétés d'un tel objet au fil du rendu.
  const { present, ref, className, style } = useUiMotion(open, { preset: 'collapse' });
  if (!present) return null;

  return (
    <div ref={ref} className={cx('mon-panneau', className)} style={style}>
      {children}
    </div>
  );
}
```

La fin de la sortie est **lue, jamais devinée** : le crochet attend les objets `Animation` du
système, filtrés sur le préfixe `ui-motion-`. Un `setTimeout` calé sur la durée se
désaccorderait le jour où le mouvement réduit la ramène à zéro, où un thème la change, ou où
la classe ne s'applique pas. Ces trois cas donnent ici zéro animation à attendre, donc un
démontage immédiat, gratuitement.

`onExited` prévient une fois l'élément parti : c'est ce qui permet à une file de toasts de
retirer son entrée au bon moment plutôt qu'à l'ouverture de la sortie.

### API

<ArgTypes of={MotionStories} />

Le banc d'essai n'expose que trois réglages ; le crochet en accepte plus, tous facultatifs :
`preset`, `disabled`, `duration`, `delay`, `easing`, `enterEasing`, `leaveEasing`, `distance`,
`scale` et `onExited`.

## Les classes, sans le crochet

Les préréglages sont de simples classes globales, livrées dans la feuille du paquet. Un
élément qui n'a pas besoin d'être retenu peut les porter directement :

```html
<div class="ui-motion-slide-down-enter">…</div>
```

Le contrat est stable et **partagé avec le starter Angular** :
`ui-motion-<preset>-enter` et `ui-motion-<preset>-leave`.

## Transition d'état, pour un élément monté

```scss
@use 'utils';

.mon-panneau {
  opacity: 0;
  @include utils.motion-transition(opacity, translate);

  &._open {
    opacity: 1;
  }
}
```

## Panneau du calque supérieur

Un `[popover]` ou un `<dialog>` n'a besoin de rien en JavaScript : `utils.overlay-motion`
décrit son état fermé, et la plateforme fait le reste avec `transition-behavior:
allow-discrete` et `@starting-style`.

```scss
@include utils.overlay-motion {
  opacity: 0;
  scale: 0.96;
}
```

`utils.overlay-motion-enter` en est la variante « entrée seule » : la sortie est instantanée,
pour un panneau dont l'ancre peut disparaître sous lui, un sous-menu en cascade typiquement.

## Jetons : primitives et recettes

Le mouvement suit le même modèle que la couleur. Les **primitives** `--transition-*`
(collection `transitions`) sont les valeurs. Les **recettes** `--motion-*` (collection
`motion`) les associent à un usage : une recette, c'est une durée et une courbe, en alias
d'une primitive. Les composants lisent les recettes, jamais les primitives. Les noms sont
les mêmes dans le starter Angular.

Chaque recette vaut aujourd'hui le timing que le kit avait avant elles. Pour recadencer
**tout le kit**, surchargez une recette sur `:root` (`--motion-hover-duration: 120ms`) :
seuls les usages qu'elle couvre changent. Surcharger une primitive (`--transition-default`)
fonctionne toujours, et touche toutes les recettes qui la référencent.

Le mixin `utils.control-transition` choisit la recette selon la propriété : `transform`,
`top` ou `width` déplacent quelque chose et suivent `toggle`, une couleur ou une opacité suit
`hover`. Le hook `--ui-control-transition-duration` règle toujours les deux à la fois.

## Couper le mouvement

Trois niveaux, du plus étroit au plus large, et le plus large gagne toujours.

<table className="doc-table">
  <thead>
    <tr>
      <th>Niveau</th>
      <th>Comment</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td>Un élément</td>
      <td><code>useUiMotion(open, &#123; disabled: true &#125;)</code>, ou la prop <code>motion</code> du composant concerné.</td>
    </tr>
    <tr>
      <td>Toute l'application</td>
      <td><code>data-motion="off"</code> sur <code>&lt;html&gt;</code> : neutralise les animations <strong>et</strong> les transitions du kit. C'est le réglage à poser dans les tests de bout en bout.</td>
    </tr>
    <tr>
      <td>Préférence système</td>
      <td><code>prefers-reduced-motion: reduce</code> bascule la collection <code>motion</code> dans son mode <code>Reduced</code> : glissement à 0, échelle du <code>zoom</code> à 1, recettes de déplacement à 80ms. Chaque préréglage et chaque panneau devient un fondu court : l'état change, sans mouvement. Les changements de couleur (<code>hover</code>) gardent leur durée. Un composant qui pose sa propre garde <code>utils.motion-reduce</code> (tiroir, bottom sheet, barre latérale, tooltip) reste instantané.</td>
    </tr>
  </tbody>
</table>

Aucun des trois ne casse le démontage : sans animation à attendre, le crochet retire
l'élément tout de suite.
