# Ripple

Onde de pression sur les éléments interactifs : au `pointerdown`, une vague part du point de
contact et couvre l'élément. Purement décorative, elle confirme que le clic a été reçu, y
compris avant que l'action n'aboutisse.

L'effet s'active **à trois portées** (application, sous-arbre, élément) et se règle
**uniquement par des propriétés CSS**, héritées comme les autres jetons. Quatorze composants
du kit sont **équipés d'office** : les activer ne demande aucune retouche, et chacun se coupe
par `ripple={false}`.

### 1. Globale

```tsx
import { UiRippleProvider } from '@4sh/ui-kit-react/ripple';

<UiRippleProvider>
  <App />
</UiRippleProvider>;
```

Un seul écouteur `pointerdown` sur `body`. Ondulent alors les **contrôles du kit**, qui se
déclarent eux-mêmes par `data-ripple="on"` sur le contrôle natif qu'ils rendent, et tout
élément marqué de la même façon. Les boutons de l'application ne sont **pas** concernés par
défaut : un Design System ne peint pas d'onde sur un balisage qui n'est pas le sien. Pour les
inclure :

```tsx
import { UiRippleProvider, UI_RIPPLE_INTERACTIVE_SELECTOR } from '@4sh/ui-kit-react/ripple';

// button, [role="button"], a[href], [data-ripple="on"]
<UiRippleProvider selector={UI_RIPPLE_INTERACTIVE_SELECTOR}>…</UiRippleProvider>;
```

`global={false}` ne fait que poser ce sélecteur pour les portées locales qu'il contient.

### 2. Locale

```tsx
function Toolbar() {
  const scope = useUiRippleScope();
  return (
    <div className="toolbar" {...scope}>
      <UiButton label="Enregistrer" />
      <button type="button">Annuler</button>
    </div>
  );
}
```

Même mécanique, bornée à un sous-arbre : un écouteur sur le conteneur. `selector` restreint
ou élargit ce qui y ondule.

### 3. Ciblée

```tsx
const ripple = useUiRipple({ centered: true });
<button type="button" aria-label="Fermer" {...ripple}>
  …
</button>;
```

Les crochets rendent `ref` et `data-ripple`, à reverser sur l'élément. Sur un composant du
kit, préférer sa prop `ripple` ou une portée : c'est son contrôle natif qu'il faut atteindre.

En sont absents les contrôles dont le changement d'état **est** le retour visuel, sur une
cible trop petite (case à cocher, radio, interrupteur, curseur, note), les surfaces de
révélation (accordéon, étapes), les ✕ de fermeture et de suppression, les liens en ligne,
et les lignes de tableau, où une onde pleine largeur est envahissante.

## Personnalisation

Aucune option d'apparence côté TypeScript : tout passe par les propriétés CSS, posées sur
`:root`, sur un conteneur ou sur l'élément lui-même.

## Performance

- Un seul écouteur `pointerdown`, **passif**, par activation : une portée ne coûte pas un
  écouteur par bouton.
- Rien n'est créé ni mesuré avant la première pression. Chaque vague est une `<span>` retirée
  à la fin de son animation, et quatre au plus coexistent sur un même élément.
- L'animation ne porte que sur `transform` et `opacity` : ni mise en page, ni repeinture de
  l'hôte.

## Désactivation et accessibilité

- **Par élément ou sous-arbre** : `ripple={false}` sur un composant du kit,
  `data-ripple="off"` sur n'importe quel ancêtre, ou `enabled: false` sur un crochet.
- **Mouvement réduit** : la préférence système, ou l'interrupteur `data-motion="off"` du kit,
  coupe toute onde.
- **Lecteur d'écran** : la couche porte `aria-hidden`, rien n'est annoncé.
- **Clavier** : l'onde suit le pointeur ; `Entrée` et `Espace` gardent l'état `pressed` du
  contrôle, qui est leur retour visuel.
